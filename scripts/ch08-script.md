## 7-1 什麼是陣列？

來，問你一個問題。你是一個老師，你的班上有 30 個學生，期中考完了，你要把 30 個人的成績存進電腦。你打算怎麼宣告變數？

`int score_王小明 = 85;`
`int score_李大華 = 90;`
`int score_陳美玲 = 78;`

……然後宣告到第八個你就放棄了，對吧？

說真的，就算你肯宣告，你之後要怎麼處理這 30 個變數？你不可能在迴圈裡對它們做任何事，因為它們根本沒有規律可以迭代。

陣列就是來救你的。陣列的概念很像是停車場格位——你不需要幫每個格位取名字，你只需要說「3 號格位」、「17 號格位」，就能找到任何一輛車。一個停車場名字，加上格位編號，搞定。

陣列的英文是 Array，它有兩個鐵律：第一，**大小固定**，你宣告時說幾格就幾格，不能動態縮放；第二，**型別相同**，你放整數的陣列不能突然塞一個字串進去。這兩個限制聽起來很死板，但正是因為這樣，它才能在記憶體裡排得整整齊齊，讓你用號碼快速找到任何一個元素。

---

## 陣列 vs 多個變數 + 索引概念

好，我們來看一下有陣列之後，世界變得多美好。

```java
int[] scores = {85, 90, 78, 92, 88};
```

五個成績，一行解決。要取第一個成績，`scores[0]`。要取最後一個，`scores[4]`。

等一下，`scores[0]`？為什麼是 0？為什麼不是從 1 開始？

這是一個讓無數初學者抓狂的設計，但其實有它的道理。索引（Index）本質上是「距離第一個元素多遠」的意思，第一個元素距離自己的距離是 0，所以索引是 0。這個設計在計算記憶體位址的時候非常方便，你就先背下來：**從 0 開始，最後一個是 length - 1**。

你可以把陣列想成蛋盒。一盒六顆蛋，盒子上有六個格子，格子從 0 號到 5 號。你說「給我 0 號格子的蛋」，就是第一顆。你說「給我 5 號的蛋」，就是最後一顆。你說「給我 6 號的蛋」——不好意思，這盒蛋沒有 6 號，你要被 Java 白眼了。

## 7-2 陣列的宣告語法

陣列的宣告有三種寫法，我直接告訴你哪種最常用。

第一種：先宣告，再 new。

```java
int[] scores;
scores = new int[5];
```

這種適合你已經知道大小但還不知道內容的情況。比如你要讀使用者輸入，先開五個格子，等一下再填資料。

第二種：宣告同時 new。

```java
int[] scores = new int[5];
```

跟第一種一樣，只是寫在同一行。

第三種：宣告並直接初始化。

```java
int[] scores = {85, 90, 78, 92, 88};
```

這是最常用、最清楚的寫法。你已經知道所有資料，就直接寫出來，乾淨俐落。

順帶一提，有人會這樣宣告：`int scores[]`，中括號放在變數名稱後面而不是型別後面。這是 C 語言的寫法，Java 也支援，但不推薦。你在 Java 世界，就用 Java 的風格，中括號放型別後面。

---

## 陣列預設值與 length 屬性

用 `new` 建立陣列的時候，Java 很貼心地幫你把每個格子清空——整數清成 0，布林清成 false，小數清成 0.0，物件清成 null。

你不用擔心格子裡有奇怪的殘留值，Java 幫你收好了。

另外一個很常用的屬性是 `length`。注意，是**屬性**，不是**方法**——你寫 `scores.length` 不要加括號，不是 `scores.length()`。這個細節很多人搞混。

`arr.length` 直接告訴你這個陣列有幾個元素，非常簡單，非常好用。

---

## ArrayIndexOutOfBoundsException

好，這個是今天的第一個必踩地雷，我叫你們記住它的名字：**ArrayIndexOutOfBoundsException**。

翻譯一下：陣列索引超出邊界例外。大白話就是「你伸手進了一個不存在的格子」。

一個大小為 3 的陣列，有效索引是 0、1、2。你去存取 `arr[3]`，Java 不會客氣地給你一個 0，它會直接把你的程式炸掉——這個例外是 RuntimeException，一發生就崩潰，沒有商量餘地。

說真的，這個錯誤犯過一次你就不會忘了。迴圈的終止條件要寫 `i < arr.length`，不是 `i <= arr.length`。這個差一個等號，就是天堂和地獄的差別。你一定要把這個刻在腦子裡。

---

## 走訪陣列：for 迴圈

走訪陣列最基本的方式就是 for 迴圈。有兩種：

第一種是傳統 for 迴圈，你需要索引的時候用：

```java
for (int i = 0; i < scores.length; i++) {
    sum += scores[i];
}
```

第二種是增強型 for 迴圈，也叫 for-each，你不需要索引、只需要值的時候用：

```java
for (int s : scores) {
    System.out.println(s);
}
```

增強型 for 的讀法是「對 scores 裡的每一個 int s，做以下事情」。寫起來更短，讀起來更像人話。但注意，如果你需要知道「這個元素在第幾個位置」，增強型 for 就做不到，得回頭用傳統 for。

---

## Arrays 工具類別（介紹 + 範例）

Java 知道你懶得自己寫排序，所以給了你一個現成的工具箱：`java.util.Arrays`。裡面全是靜態方法，要用之前 import 一下就好。

最常用的幾個：

- `Arrays.sort(arr)`：幫你把陣列從小排到大，直接修改原陣列。
- `Arrays.toString(arr)`：把陣列變成可以看的字串，像 `[5, 2, 8]` 這樣。
- `Arrays.fill(arr, val)`：把每個格子都填成同一個值，常用來重置。
- `Arrays.copyOf(arr, len)`：複製陣列，可以指定新的長度。

這裡有個新手常踩的坑：你如果直接 `System.out.println(arr)`，輸出結果是一串奇怪的文字，像 `[I@7852e922`，這是記憶體位址，完全不是你想要的東西。你要先用 `Arrays.toString(arr)` 轉換，才能看到裡面的值。

把 `Arrays.toString` 記下來，它幫了我無數次忙。

## 7-3 原始型態 vs 參照型態

好，現在我們進入今天最燒腦的部分。你們準備好了嗎？

Java 的資料型態分兩大類：原始型態（Primitive）和參照型態（Reference）。

原始型態你很熟了：`int`、`double`、`boolean`、`char`。這些變數，**直接儲存值**。就像你口袋裡放了一張百元鈔票，你要用的時候直接掏出來用，乾脆俐落。

參照型態就不同了：`String`、陣列、任何物件。這些變數儲存的不是值，而是**記憶體位址**——一張地圖，地圖上面寫著「真正的資料在哪裡」。你的口袋裡裝的不是鈔票，是一個藏寶圖。

聽起來很抽象？我們看記憶體圖解。

---

## Stack vs Heap 記憶體圖解

Java 的記憶體分兩個主要區域：Stack 和 Heap。

Stack 是「堆疊記憶體」，存放區域變數、方法呼叫紀錄。速度很快，但空間有限，而且東西用完就自動釋放。

Heap 是「堆積記憶體」，存放所有物件和陣列的實際資料。空間大，但需要 GC 來管理回收。

現在看這段程式碼：

```java
int age = 25;
int[] scores = {85, 90};
```

`age` 是原始型態，25 這個值**直接住在 Stack 裡**，簡單明瞭。

`scores` 是陣列（參照型態）。Stack 裡面存的是一個位址，比方說 `0x1A2B`，這個位址指向 Heap 裡面的一塊空間，那塊空間裡才是真正的 `{85, 90}`。

所以 `scores` 這個變數，本質上是一個「快遞單號」，不是貨物本身。

---

## 陣列賦值的陷阱

現在是今天最重要的一個坑，請大家收起手機聽我說。

```java
int[] a = {1, 2, 3};
int[] b = a;
b[0] = 99;
System.out.println(a[0]); // 輸出多少？
```

你可能以為是 1，但答案是 **99**。

為什麼？因為 `b = a` 這行，**只是把 a 的位址複製給 b**。現在 a 和 b 這兩個變數，指向的是 Heap 上**同一塊**記憶體。你透過 b 修改第 0 個格子，a 當然也看到改變了——因為它們根本就是同一個抽屜！

用租屋做比喻：a 是你的門牌號碼，b = a 是你把門牌號碼抄給別人。結果那個人跑去你家改了裝潢，你回家一看傻眼——房子是同一間啊。

如果你真的要複製一份獨立的陣列，用這個：

```java
int[] b = Arrays.copyOf(a, a.length);
```

這樣才是真正地「搬出去住」。

## 7-4 什麼是垃圾回收（GC）？

好，接下來聊一個跟清潔有關的話題。

你學過 C 語言的話，你知道記憶體要自己管理：用 `malloc` 申請，用 `free` 釋放。忘了 `free`？恭喜你，記憶體洩漏，程式慢慢變胖，最後崩潰。

Java 不讓你操心這件事。它雇了一個自動清潔工，叫做 **Garbage Collector（GC）**，垃圾回收器。GC 的工作就是巡邏 Heap，找出那些「沒有人再用的物件」，把它們清掉，釋放記憶體。

什麼叫「沒有人再用」？就是沒有任何變數指向它的物件。

```java
int[] arr = new int[]{1, 2, 3};
arr = null; // arr 不再指向那個陣列了
```

你把 arr 設成 null，就等於把藏寶圖丟掉了。那塊 Heap 上的資料，從這一刻起，沒有任何人知道它在哪裡，GC 就會在某個時間點把它清掉，釋放那塊空間。

這就是自動倒垃圾——你不用親手去倒，但你要知道「什麼時候垃圾桶滿了會有人來收」。

---

## GC 的觸發時機與 null 的作用

GC 的觸發時機，是由 JVM 自己決定的——通常是 Heap 記憶體快滿的時候。

你可以呼叫 `System.gc()` 來「建議」JVM 執行 GC，但注意，那只是建議。JVM 可以理你，也可以完全無視你。你不能命令 GC 立刻出動。

那我們能做什麼？可以主動把不需要的大物件設成 null，讓 GC 有機會把它列入清理名單。

比如你處理了一個超大的百萬元素陣列，用完之後：

```java
bigArray = null;
```

這個動作本身不會立刻回收記憶體，但你把藏寶圖丟掉了，GC 下次來掃的時候就知道可以清掉它。

GC 還有一個好處：它幫你完全避免了 C/C++ 裡那種「懸空指標」（Dangling Pointer）的問題——你不可能拿到一個指向已釋放記憶體的指標，因為 GC 在回收之前會確認沒有人還在用那塊記憶體。

## 7-5 多維陣列：陣列的陣列概念

一維陣列是一排格子，那如果你需要一個「表格」呢？二維陣列登場。

但這裡有個 Java 很獨特的設計，要特別說明：Java 的二維陣列，本質上是「陣列的陣列」。

也就是說，`int[][] matrix` 這個變數，存的是一個「陣列的參照」，而這個陣列裡面的每一個元素，本身又是一個 `int[]`。

```
matrix
  ├── matrix[0] → [1, 2, 3]   ← 一個獨立的 int[]
  ├── matrix[1] → [4, 5, 6]   ← 一個獨立的 int[]
  └── matrix[2] → [7, 8, 9]   ← 一個獨立的 int[]
```

這跟 C 語言的二維陣列不一樣。C 的二維陣列是一塊連續的記憶體，Java 的每一列是獨立的物件，住在 Heap 的不同地方。

這個設計的好處是——每一列可以有不同長度，也就是我們等一下要說的「不規則陣列」。

---

## 二維陣列的宣告與走訪

宣告一個 3×3 的矩陣：

```java
int[][] matrix = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};
```

走訪它要用**巢狀 for 迴圈**，外層跑列，內層跑欄：

```java
for (int i = 0; i < matrix.length; i++) {
    for (int j = 0; j < matrix[i].length; j++) {
        System.out.print(matrix[i][j] + " ");
    }
    System.out.println();
}
```

這裡有一個細節要注意：內層的終止條件是 `matrix[i].length`，不是 `matrix.length`。因為每一列是獨立的陣列，各自有自己的 length。如果你的矩陣是規則的（每列等長），這兩個值相同，但習慣上還是要寫對。

---

## 不規則陣列（Jagged Array）

因為每一列是獨立的陣列，你可以讓每列有不同的長度——這就是「不規則陣列」，英文叫 Jagged Array，字面意思是「鋸齒狀的」。

```java
int[][] jagged = new int[3][];
jagged[0] = new int[2];
jagged[1] = new int[4];
jagged[2] = new int[1];
```

第一行先建立一個「有 3 個參照」的陣列，但每個參照指向哪裡還沒決定。之後再逐一指定每列的大小。

這種設計在很多實際場景很有用，比如你要存學校每個年級的學生名單，每個年級人數不同，用不規則陣列就很自然。

---

## 7-6 String[] args 是什麼？

你每天寫的 Java 程式開頭都有這一行：

```java
public static void main(String[] args)
```

那個 `args` 到底是什麼？今天終於可以告訴你：它是一個**字串陣列**，裡面存放你在命令列執行程式時，在後面額外傳入的參數。

比如你執行：

```
java Hello Alice Bob 123
```

這時候，`args[0]` 是 `"Alice"`，`args[1]` 是 `"Bob"`，`args[2]` 是 `"123"`，`args.length` 是 3。

注意，這些都是字串，不管你傳的看起來是不是數字，進來就是 String。你要用就要自己轉型。

另外，如果沒有傳任何參數，`args` 不是 `null`，它是一個長度為 0 的空陣列。這一點要記清楚，因為如果你直接去存取 `args[0]` 卻沒有傳參數，你又會見到那個老朋友：ArrayIndexOutOfBoundsException。

---

## 從 args 讀取整數

命令列傳進來的永遠是字串，你要整數就用 `Integer.parseInt`，要小數就用 `Double.parseDouble`。

```java
int a = Integer.parseInt(args[0]);
int b = Integer.parseInt(args[1]);
System.out.println(a + " + " + b + " = " + (a + b));
```

執行 `java Calculator 10 25` 就會輸出 `10 + 25 = 35`。

養成好習慣：先檢查 `args.length`，確認使用者有傳夠多的參數，再去取用。這樣程式才有防禦性，不會隨便崩潰。

如果使用者傳了 `"abc"` 進來，`Integer.parseInt("abc")` 會拋出 `NumberFormatException`，這個之後學例外處理的時候會學到怎麼優雅地處理它。

## 7-7 矩陣加法

好，我們現在用二維陣列做一個實際的事情：矩陣加法。

規則很簡單：兩個大小相同的矩陣，把對應位置的數字相加，放進新矩陣的同一個位置。

```java
int[][] a = {{1, 2}, {3, 4}};
int[][] b = {{5, 6}, {7, 8}};
int[][] c = new int[2][2];

for (int i = 0; i < 2; i++) {
    for (int j = 0; j < 2; j++) {
        c[i][j] = a[i][j] + b[i][j];
    }
}
```

`c[0][0] = 1 + 5 = 6`，`c[0][1] = 2 + 6 = 8`，以此類推。巢狀迴圈把所有格子都處理完。

輸出的時候，你可以用 `Arrays.toString(c[i])` 來印每一列，省掉一層迴圈，很方便。

```java
for (int i = 0; i < c.length; i++) {
    System.out.println(Arrays.toString(c[i]));
}
// [6, 8]
// [10, 12]
```

---

## 二維陣列走訪：增強型 for 迴圈

二維陣列也可以用增強型 for 來走訪，語法長這樣：

```java
for (int[] row : matrix) {
    for (int val : row) {
        System.out.print(val + "\t");
    }
    System.out.println();
}
```

外層的 `int[] row`，因為 `matrix` 的每個元素本身就是 `int[]`，所以你用 `int[]` 來接。內層的 `int val` 就是每一格的值。

不需要索引的時候，這種寫法讀起來比 `i`、`j` 的索引版本直觀多了。你看到 for-each 就知道是「把每個拿出來用」，不用去算索引有沒有超界。

## 7-8 線性搜尋（Linear Search）

最後的專題：線性搜尋。

線性搜尋的邏輯超級直觀：從第一個元素開始，一個一個比對，找到目標就回傳它的索引，走完整個陣列都沒找到就回傳 -1。

```java
public static int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) {
            return i;
        }
    }
    return -1;
}
```

簡單到有點像廢話的程度，但這就是它的精髓。

這個演算法的時間複雜度是 O(n)——最壞情況要看完所有元素才能確定找不到。如果你的資料有排過序，可以用更快的二分搜尋（Binary Search，O(log n)），那是之後的話題。

回傳 -1 來表示「找不到」是業界慣例。Java 自己的 `String.indexOf` 也是這樣設計的。所以你寫的搜尋函式，也要遵循這個慣例，讓別人一看就懂。

## 專題：簡單計算器（命令列版）

最後這個小專案，把本章所有重點串起來：命令列參數、字串轉數字、switch 表達式。

執行 `java Calc 10 + 5`，輸出 `10.0 + 5.0 = 15.0`。

這裡用了 Java 14 之後的 switch 表達式語法：

```java
double result = switch (op) {
    case "+" -> a + b;
    case "-" -> a - b;
    case "*" -> a * b;
    case "/" -> b != 0 ? a / b : Double.NaN;
    default  -> Double.NaN;
};
```

箭頭語法讓每個 case 只有一行，乾淨俐落。除以 0 的情況回傳 `Double.NaN`（Not a Number），這是 Java 處理非法數學運算的標準作法。

這個計算器不完美——它不會做四則運算的優先順序，也不支援括號——但作為一個「整合本章知識點的練習」，它很剛好。

## 練習 1：找出最大值

出場了，練習題。這是第一道：給你陣列 `{34, 17, 89, 45, 23, 67}`，找出最大值和它的索引位置。不能用 `Arrays.sort()`，要自己用迴圈。

思路是這樣的：你有沒有看過選班長的過程？先假設第一個人是班長，然後讓每個候選人出來 PK，如果有人比班長強，就換人當。最後站著的那個人就是班長。

翻譯成程式：先假設 `arr[0]` 是最大值，記下它的值和索引。然後從索引 1 開始走訪，每次比對，如果當前元素比記錄的最大值還大，就更新。迴圈跑完，你的記錄就是答案。

關鍵細節：從索引 1 開始走，因為已經假設 0 是最大值了，不需要和自己比。

## 練習 2：轉置矩陣

第二道：給你一個 2×3 的矩陣，求它的轉置矩陣（3×2）。

轉置的意思就是把行跟列對調：原本第 0 行第 1 列的元素，移到轉置矩陣的第 1 行第 0 列。規律是 `transposed[j][i] = matrix[i][j]`。

實作步驟：宣告一個 `new int[3][2]` 的新陣列，然後用巢狀迴圈走訪原矩陣，把每個元素放到轉置位置。

注意轉置矩陣的大小是反過來的：原本 2 列 3 欄，轉置後是 3 列 2 欄。宣告的時候不要宣告錯。

這道題練的是「對二維陣列索引的掌握」，`[i][j]` 和 `[j][i]` 的交換這個概念要能很直覺地想出來，往後處理圖像、矩陣運算都會用到。
