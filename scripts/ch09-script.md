## 第一部分：認識物件與類別

（過場）

第一部分，我們先建立最基本的概念：什麼是類別？什麼是物件？

---

## 8-1 類別與物件的關係

好，我問你一個問題。

建築師在蓋房子之前，會先做什麼？畫設計圖對吧。設計圖上面寫著：幾個房間、幾間浴室、客廳多大、哪裡開窗。然後工人拿著這張設計圖，蓋出一棟棟實際的房子。

**類別就是設計圖，物件就是根據設計圖蓋出來的房子。**

更具體說：

- 類別（Class）定義了「這種東西長什麼樣子」。比如 Car 類別，定義了車有品牌、有顏色、有時速，還有加速、煞車這些行為。
- 物件（Object）是「真正存在的那一台車」。你的 Toyota 是一個物件，你同學的 Honda 是另一個物件，它們都是根據 Car 這張設計圖造出來的，但是各自獨立。

所以：**欄位（Field）是狀態，方法（Method）是行為**。

你的車現在時速 80，他的車時速 120——這是各自的狀態。但兩台車都可以加速、煞車——這是共用的行為，方法只需要定義一次。

---

## 8-1 現實世界比喻：學生

剛才用車子舉例，現在換一個更貼近大家的例子——學生。

你有沒有想過，全校幾千個學生，他們本質上都是「學生」這個類型。有學號、有名字、有成績，會讀書、會考試。這些「共同特徵」就是 Student 這個類別定義的事情。

但每個學生又不一樣。小明的學號是 1001，成績 90 分；小華的學號是 1002，成績嘛⋯⋯就不說了。他們是兩個不同的物件，各自有自己的狀態。

看程式碼：

```java
class Student { ... }  // 設計圖

Student s1 = new Student();  // 小明這個物件
Student s2 = new Student();  // 小華這個物件
```

`new` 這個關鍵字就是「按照設計圖，蓋出一棟房子」的指令。每呼叫一次 new，就多一個獨立的物件。

## 第二部分：定義類別與物件

（過場）

好，概念建立了。接下來我們實際動手——怎麼用 Java 寫出一個類別？

---

## 8-2 class 語法結構 + 建立物件與存取成員

寫一個類別，語法其實很直觀。

`class Car { }` ——就這樣，一個類別的殼就出來了。

裡面放什麼？兩種東西：**欄位**（資料）和**方法**（行為）。

```java
class Car {
    String brand;   // 欄位：品牌
    int speed;      // 欄位：時速

    void accelerate() {   // 方法：加速
        speed += 10;
    }
}
```

注意命名習慣喔：類別名稱首字大寫，`Car`、`Student`、`BankAccount`；欄位和方法名稱首字小寫，`brand`、`speed`、`accelerate()`。這是 Java 界的共識，不是強制規定，但你如果不遵守，其他工程師看到你的程式碼會皺眉頭。

---

建立物件呢？用 `new`：

```java
Car myCar = new Car();
myCar.brand = "Toyota";
myCar.speed = 0;
myCar.accelerate();
System.out.println(myCar.speed); // 10
```

用「點」來存取欄位和方法。`myCar.brand` 就是「myCar 這台車的品牌」，`myCar.accelerate()` 就是「讓 myCar 這台車加速」。

這裡有個細節要記住：`new` 做了三件事。第一，在 Heap 記憶體裡挖一塊空間；第二，把所有欄位初始化為預設值（數字是 0、boolean 是 false、物件是 null）；第三，把那塊記憶體的位址回傳給你。所以 `myCar` 裡面存的不是物件本體，而是物件的**地址**。這個觀念等一下談參照型態的時候還會用到。

## 第三部分：類別的基本實例

（過場）

來了來了，這一部分我們把 Car 類別做得更完整，真正動起來。

## 8-3 完整 Car 類別 + 建立物件操作

好，剛才的 Car 只有品牌和時速，現在加上顏色，再補一個 `displayInfo()` 方法：

```java
class Car {
    String brand;
    String color;
    int speed;

    void accelerate(int amount) {
        speed += amount;
    }

    void displayInfo() {
        System.out.println(brand + " / " + color
            + " / 時速：" + speed + " km/h");
    }
}
```

這個 `accelerate` 現在有參數了，你可以指定要加速多少。這樣比較彈性，對吧？

然後在 main 裡面用它：

```java
Car c1 = new Car();
c1.brand = "Toyota";
c1.color = "紅色";
c1.speed = 0;

c1.accelerate(60);
c1.displayInfo();
// 輸出：Toyota / 紅色 / 時速：60 km/h
```

是不是開始有感覺了？類別是模板，物件是實體，用點來操控物件的一切。這個模式會貫穿整個 Java 物件導向的世界。

## 第四部分：類別含多個物件的應用

（過場）

一張設計圖，可以蓋很多棟房子。這一部分我們來看，多個物件怎麼管理。

---

## 8-4 建立多個物件 + 物件陣列

每次呼叫 `new`，就建立一個全新的、獨立的物件：

```java
Car c1 = new Car();
c1.brand = "Toyota";
c1.speed = 80;

Car c2 = new Car();
c2.brand = "Honda";
c2.speed = 100;
```

c1 和 c2 是兩個不同的物件，住在記憶體的不同地方。你改 c1 的速度，c2 完全不受影響。它們只是用同一個類別創建出來的，就像同一個媽生的雙胞胎，長得一樣但是是兩個人。

---

那如果有十台車、一百台車呢？一個個宣告變數太慘了。這時候就需要**物件陣列**。

但要注意！物件陣列有個「兩步驟陷阱」，很多初學者在這裡踩坑：

**第一步**：`Car[] cars = new Car[3];` ——這只是建立了「停車場」，三個停車格，每格預設是 null。車還沒有！

**第二步**：逐一 new Car 放進去：

```java
cars[0] = new Car();
cars[0].brand = "Toyota";
cars[0].speed = 80;
```

停車場建好了，還要把車一台一台開進去。這是很多人忘記做的步驟，然後遇到 `NullPointerException` 一臉茫然——對，就是沒開車進來！

---

陣列建好之後，遍歷就很方便：

```java
for (Car c : cars) {
    c.displayInfo();
}
```

for-each 語法，簡潔優雅。一行搞定所有車的資訊。

## 第五部分：類別的參照資料型態

（過場）

好，這部分非常重要，也是最多人搞混的地方。聽好了喔。

---

## 8-5 物件賦值 = 複製參照 + 記憶體圖解

我要考你一個問題：

```java
Car c1 = new Car();
c1.brand = "Toyota";
c1.speed = 80;

Car c2 = c1;
c2.speed = 999;

System.out.println(c1.speed); // 你覺得印出什麼？
```

如果你說「80」，那你就跟大部分初學者一樣踩坑了。答案是 **999**。

為什麼？因為 `c2 = c1` **不是複製物件**，而是複製「地址」。c1 裡面存的是一個記憶體位址，`c2 = c1` 之後，c2 也存了同一個地址。所以 c1 和 c2 根本在指同一台車！

用圖解想像：c1 和 c2 是兩張便利貼，上面都寫著「停車場 B3 格」。你不管透過哪張便利貼去改那台車，改的都是同一台車。

這就是「參照型態」的核心。物件變數存的是「地址（參照）」，不是物件本體。

---

## 8-5 null 參照

那如果一個物件變數連地址都沒有呢？那就是 `null`。

```java
Car c = null;
c.displayInfo(); // NullPointerException！！
```

null 就是「這張便利貼是空的，啥也沒寫」。你用空便利貼去停車場找車，當然找不到，程式就爆炸了，這就是惡名昭彰的 **NullPointerException**，簡稱 NPE。

安全的做法是先判斷：

```java
if (c != null) {
    c.displayInfo();
} else {
    System.out.println("尚未建立車輛");
}
```

先確認便利貼上有寫地址，再去找車。這個習慣會救你很多次。

## 第六部分：再談方法

（過場）

方法（Method）是物件的行為，這部分我們要深入看三件事：傳值、多載、this。

---

## 8-6 Pass by Value（一）：基本型態

Java 有一個鐵則，不管什麼時候都成立：**方法參數永遠是「複製值」傳入**。

先看基本型態：

```java
static void addTen(int x) {
    x += 10;
}
int n = 5;
addTen(n);
System.out.println(n); // 5
```

n 還是 5。因為傳進去的是 n 的**副本**，方法裡改的是那個副本，外面的 n 完全不知道發生了什麼事。

想像你去影印了一份合約，然後在影本上塗塗改改——原本還是乾乾淨淨的。基本型態就是這樣。

---

## 8-6 Pass by Value（二）：物件型態

但如果傳進去的是物件呢？這裡要小心了：

```java
static void changeSpeed(Car c) {
    c.speed = 999;  // 修改欄位：外面感受得到！
}

static void reassign(Car c) {
    c = new Car();  // 重新賦值：外面感受不到
    c.speed = 0;
}

Car myCar = new Car();
myCar.speed = 80;

changeSpeed(myCar);
System.out.println(myCar.speed); // 999

reassign(myCar);
System.out.println(myCar.speed); // 999（沒有變！）
```

傳物件進去，複製的是「地址」。所以 `changeSpeed` 裡面透過那個地址去改欄位，改的是同一台車，外面看得到。

但 `reassign` 裡面 `c = new Car()` ——這是讓方法裡的 c 指向一台新車，原本外面的 myCar 還是指著舊車，老神在在，完全沒感覺。

記住口訣：**改欄位有影響，換地址沒影響**。

---

## 8-6 方法多載（Overloading）

多載的概念很生活化。你有沒有一個朋友，你叫他幫忙，他會看情況做不同的事？你說「幫我算一下」，他問：「算兩個數字還是三個？整數還是小數？」

Java 的多載就是這樣——同一個方法名稱，根據你傳入的參數不同，自動選擇對應的版本：

```java
class Multiplier {
    int multiply(int a, int b) { return a * b; }
    int multiply(int a, int b, int c) { return a * b * c; }
    double multiply(double a, double b) { return a * b; }
}
```

三個 `multiply`，但參數不同。Java 編譯器很聰明，看你傳什麼就用哪個版本，完全自動。

但有一個陷阱：**只有回傳型別不同，不算多載**，會編譯錯誤。因為 Java 沒辦法光看呼叫端就知道你要哪個版本。參數的數量或型別才是區分的依據。

---

## 8-6 this 關鍵字

`this` 這個關鍵字初學者常常搞混，但其實概念很簡單——**this 就是「我自己這個物件」**。

最常用的場景是建構子（或 setter）：

```java
class Car {
    String brand;
    int speed;

    Car(String brand, int speed) {
        this.brand = brand;  // this.brand = 欄位；brand = 參數
        this.speed = speed;
    }
}
```

你看，建構子的參數名稱和欄位名稱一樣，都叫 `brand`。這時候如果直接寫 `brand = brand`，Java 會以為兩個都是參數，什麼都沒改到。

加上 `this.` 就很清楚了：`this.brand` 是「我這個物件的 brand 欄位」，右邊的 `brand` 是參數。左右清清楚楚，不會搞混。

## 8-7 Local vs Instance 變數 + Scope 遮蔽

兩種變數要分清楚：

**Instance 變數**（實例變數）：宣告在類別裡、方法外面。物件活著，它就活著。有預設值（數字 0、boolean false、物件 null）。

**Local 變數**（區域變數）：宣告在方法或區塊裡面。方法結束，它就消失。沒有預設值，你必須在用它之前自己賦值，不然編譯器會叫你。

```java
class Counter {
    int count = 0;   // instance 變數，整個物件都看得到

    void increment() {
        int step = 1;  // local 變數，只有這個方法看得到
        count += step;
    }
    // 這裡 step 已經不存在了
}
```

然後有一個很常見的狀況叫「遮蔽（Shadowing）」：local 變數和 instance 變數同名，local 會蓋住 instance。這時候就要用 `this.` 來指定：`this.speed = speed;` ——左邊是欄位，右邊是參數。

這個情況在建構子和 setter 裡面超常見，一定要習慣。

## 第八部分：匿名陣列

（過場）

這一部分很短，但很實用。有時候你只需要用一次的陣列，何必幫它取名字？

---

## 8-8 匿名陣列（Anonymous Array）

一般寫法是這樣：

```java
int[] nums = {1, 2, 3};
printSum(nums);
```

先宣告一個變數 `nums`，然後傳進去。但如果這個陣列你只用一次，後面再也不會碰到它，為它取名字有點浪費。

匿名陣列就是省略取名字這個步驟：

```java
printSum(new int[]{1, 2, 3});
```

直接在呼叫的地方建立陣列，建完就傳進去，乾淨俐落。

語法：`new 型別[]{值1, 值2, 值3}`——要記得方括號裡不寫長度，長度由後面的大括號決定。

什麼時候用？當你確定這個陣列只用一次，不需要在外面再次存取的時候。讓程式碼更簡潔，少一個多餘的變數。

## 8-9 遞迴基本概念 + Factorial 階乘

遞迴是什麼？你有沒有玩過俄羅斯套娃？

大娃娃裡面有中娃娃，中娃娃裡面有小娃娃，小娃娃裡面⋯⋯啊！到最小那個了，裡面沒有娃娃了，這個就是**終止條件（Base Case）**。

遞迴就是「方法呼叫自己，但每次規模縮小一點，直到碰到終止條件就停下來」。

兩個核心要素缺一不可：

1. **Base Case**：什麼情況直接回傳，不再往下呼叫
2. **Recursive Case**：呼叫自己，並且問題規模要縮小

如果沒有 Base Case，或者問題規模沒有縮小，遞迴就會永遠呼叫下去，最後記憶體爆掉，拋出 `StackOverflowError`——就是套娃套個沒完，stack 裝不下了。

---

最經典的範例是階乘（Factorial）：

```java
static int factorial(int n) {
    if (n <= 1) return 1;        // Base Case
    return n * factorial(n - 1); // Recursive Case
}
```

`factorial(5)` 是什麼？是 5 × `factorial(4)`。`factorial(4)` 是什麼？是 4 × `factorial(3)`。一路往下，直到 `factorial(1)` 回傳 1，然後像骨牌一樣一層一層回傳：1 → 2 → 6 → 24 → 120。

這個「一層一層往下問，再一層一層回答」的過程，就是 Call Stack 的展開與回收。

---

## 8-9 遞迴呼叫堆疊展開

來看 `factorial(4)` 的完整流程：

main 呼叫 factorial(4)，factorial(4) 呼叫 factorial(3)，factorial(3) 呼叫 factorial(2)，factorial(2) 呼叫 factorial(1)。

factorial(1) 說：「我是 base case，我回傳 1。」
factorial(2) 說：「好，2 × 1 = 2，我回傳 2。」
factorial(3) 說：「好，3 × 2 = 6，我回傳 6。」
factorial(4) 說：「好，4 × 6 = 24，我回傳 24。」

看 Sequence Diagram 的圖解，就是一個「先往下、再往上」的 V 字形路線。遞迴的精髓就在這裡。

## 第十部分：河內塔問題

（過場）

遞迴學了，來挑戰它的招牌題——河內塔。這個問題看起來很難，但用遞迴想，其實很優雅。

---

## 8-10 河內塔問題說明 + 遞迴邏輯

規則很簡單：三根柱子 A、B、C。A 上面有 n 個圓盤，從大到小往上疊。目標：把所有圓盤移到 C。限制：大盤不能壓在小盤上面。

看起來好像很難，對吧？

但用遞迴思考，拆解成三步驟：

1. 把上面 n-1 個盤子，從 A 移到 B（用 C 當中轉）
2. 把最大的盤子，從 A 直接移到 C
3. 把 n-1 個盤子，從 B 移到 C（用 A 當中轉）

就這樣！Base Case 是 n=1，直接移。

程式碼：

```java
static void hanoi(int n, char from, char aux, char to) {
    if (n == 1) {
        System.out.println("移動盤 1：" + from + " → " + to);
        return;
    }
    hanoi(n - 1, from, to, aux);
    System.out.println("移動盤 " + n + "：" + from + " → " + to);
    hanoi(n - 1, aux, from, to);
}
```

這個函式只有五行，卻能解決任意 n 個盤子的河內塔。遞迴的魅力就是這樣——把複雜的重複問題，濃縮成一個優雅的遞推公式。

## 8-10 執行 hanoi(3) 的輸出

n=3 的輸出：

```
移動盤 1：A → C
移動盤 2：A → B
移動盤 1：C → B
移動盤 3：A → C
移動盤 1：B → A
移動盤 2：B → C
移動盤 1：A → C
```

共 7 步。三個盤子要 7 步，聽起來好像不多。但如果你有 64 個盤子呢？需要 2⁶⁴ - 1 步，大概是 1800 億億次。就算每秒移一步，也要移好幾千億年。

這就是為什麼河內塔是寺廟裡的傳說——據說有人在移世界末日的那 64 個盤子，移完了世界就結束了。現在你知道為什麼世界末日還沒到——因為還差得遠。

## 練習一：BankAccount 類別

好，理論說完了，動手吧。

這個練習要你設計一個銀行帳戶類別。欄位有戶主姓名 `owner` 和餘額 `balance`，方法有存款 `deposit`、提款 `withdraw`、顯示資訊 `displayInfo`。

重點是 `withdraw` 的邏輯：提款之前要先判斷餘額夠不夠。

```java
if (balance >= amount) {
    balance -= amount;
} else {
    System.out.println("餘額不足！");
}
```

這種「先檢查再操作」的防禦性寫法，是實務上的好習慣。真實的銀行系統，當然比這複雜一百倍，但核心邏輯是一樣的。

在 main 裡建立兩個帳戶，各自存款、提款，看看輸出結果。感受一下「多個物件各自獨立」這件事。

## 練習二：多載計算機

這個練習要你對 `add` 方法做多載，設計三個版本：兩個整數相加、三個整數相加、兩個浮點數相加。

```java
int add(int a, int b) { return a + b; }
int add(int a, int b, int c) { return a + b + c; }
double add(double a, double b) { return a + b; }
```

試著呼叫看看，觀察 Java 怎麼根據參數自動選擇正確的版本。

然後思考一個問題：如果只有 `int` 版本，呼叫 `add(1.5, 2.5)` 會怎樣？Java 會自動截斷小數部分，把 1.5 當成 1、2.5 當成 2 嗎？還是會報錯？動手試試看，不要只是想，**跑出來的結果才算數**。
