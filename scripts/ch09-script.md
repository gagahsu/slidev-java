## 什麼是建構方法？

你有沒有想過，當你寫 `new Dog()` 的時候，Java 到底做了什麼？

它不只是在記憶體裡挖了一塊空間給你，它還會「自動」去呼叫一個叫做**建構方法**的特殊方法，來設定這個物件的初始狀態。

就好像工廠出貨前，每台產品都要跑一道「出廠設定流程」——顏色設好、預設音量調好、語系確認——全部搞定之後才出廠。建構方法就是那道出廠設定流程。

建構方法有三個很特別的地方，聽好了：

第一，名稱**必須跟類別一樣**，大小寫都要一樣。你的類別叫 `Dog`，建構子就叫 `Dog`，不能叫 `dog`，更不能叫 `initDog`。

第二，**完全沒有回傳型態**。注意，不是 `void`，是「連 void 都不寫」。你如果寫了 `void Dog()`，Java 就把它當一般方法看，不是建構子了。

第三，只有用 `new` 才能觸發它，你沒辦法像一般方法那樣直接 `d.Dog()` 這樣呼叫。

---

## 預設建構子（無參數）

好，問題來了。如果我沒有定義任何建構子，Java 會怎樣？

它不會報錯。它很貼心地幫你偷偷補上一個空的無參數建構子——什麼都不做，但讓你可以 `new Dog()` 順利執行。

這就是「預設建構子」。

但是，這個貼心是有條件的。

一旦你自己手動定義了任何一個建構子，Java 就說：「好，你自己來，我不插手了。」預設建構子就消失了。

所以，如果你定義了 `Dog(String name)` 這個有參數建構子，然後又想 `new Dog()` 無參數地建立物件，你會得到編譯錯誤。你必須自己再補一個空的 `Dog() {}`。

這是很多初學者踩到的第一個坑，記住了喔。

---

## 自定義建構子（含參數）

有了參數的建構子，就可以在「出生的那一刻」就把資料帶進去，而不是生出來後再一個一個賦值。

想像一下，你在醫院辦出生登記，你不需要「先登記出生、再填姓名、再填生日、再填血型」，你直接一張表填完，一次搞定。這就是有參數建構子的概念。

程式碼裡有個細節要注意：`this.name = name` 這行。

左邊的 `this.name` 是「這個物件的欄位」，右邊的 `name` 是「傳進來的參數」。因為兩個名字一樣，Java 不知道你在講哪個，所以要用 `this.` 來告訴它：「左邊是我自己的，右邊是外面來的。」

沒加 `this.` 的話，等於你把參數賦值給自己，欄位永遠是空的，程式跑起來超奇怪但不報錯。這種 bug 最難找。

---

## 建構子多載（Constructor Overloading）

講到多載，其實你之前已經見過了——方法可以多載，建構子當然也可以。

同一個類別可以有好幾個建構子，條件就是「參數型態或數量不同」。

以 `Box` 這個箱子類別為例：

- `Box()` 空的，尺寸全是零，就像一個空紙箱。
- `Box(7)` 傳一個數字，代表正方體，三邊都是 7。
- `Box(10, 20, 15)` 傳三個數字，完整指定長寬高。

這樣設計的好處是彈性。你可以視情況選擇最適合的建立方式，不用每次都強迫傳一堆參數。

編譯器很聰明，它會根據你傳進來的引數數量和型態，自動幫你挑對應的建構子。你不需要做任何額外的事，它就知道該呼叫哪一個。

## 建構子多載 — 完整範例

這頁是完整程式碼，三個建構子都在裡面了。

注意看第三個：`this.w = w; this.h = h; this.d = d;`——三個欄位分別從參數接收值。

然後 `volume()` 方法直接用這三個欄位計算體積。

這個 Box 的例子很適合拿來練習，等等練習題裡我們還會用到類似的架構，先有個印象。

## this() — 呼叫另一個建構子

這個功能很妙，而且很實用。

`this()` 可以讓一個建構子去呼叫**同一個類別**裡的另一個建構子。

為什麼要這樣做？想像你有三個建構子，每一個都需要做一段「共用的初始化邏輯」，如果你每個都寫一遍，等一下邏輯要改的時候，你要改三個地方，改漏一個就出 bug 了。

用 `this()` 把共用邏輯集中在一個建構子裡，其他人都去呼叫它，這樣改一個地方就好。

但有個嚴格規定：`this()` 必須是建構子的**第一行**。不能排在後面，不能插在中間。而且每個建構子只能呼叫一次。

還有一個禁忌：不能循環呼叫。A 呼叫 B、B 再呼叫 A，Java 編譯器會直接罵你。

---

## this() — 範例

這個範例初看有點繞，我幫你拆一下。

`new Temp()` 被呼叫，它的第一行是 `this(5)`，所以先跳去 `Temp(int x)`。

進到 `Temp(int x)`，它的第一行是 `this(5, 15)`，所以再跳去 `Temp(int x, int y)`。

`Temp(int x, int y)` 裡直接印出 `5 * 15 = 75`，然後返回。

回到 `Temp(int x)`，繼續執行，印出 `5`，返回。

回到 `Temp()`，繼續執行，印出 `預設建構子`，結束。

所以輸出順序是：75、5、預設建構子。

這個就是「鏈式呼叫」，像俄羅斯娃娃一樣，最深層的先執行，再一層一層彈回來。

---

## 建構子 vs 一般方法

好，最後做個整理，建構子和一般方法到底差在哪。

名稱：建構子必須跟類別同名，一般方法隨便你取。

回傳型態：建構子連 void 都不寫，一般方法一定要宣告回傳型態。

呼叫方式：建構子只能透過 `new`，一般方法用物件點出來呼叫。

用途：建構子負責「初始化物件」，一般方法負責「定義物件的行為」。

繼承：建構子不被繼承，一般方法可以。

這表格建議拍下來，因為考試很喜歡考這個。

## 封裝的概念

說真的，封裝這個概念超好理解，因為你每天都在用它。

你去 ATM 領錢，你按幾個按鈕，錢就出來了。你不會直接打開機器，伸手把錢抓出來。為什麼？因為 ATM 設計了「你只能透過指定的介面操作，不能直接碰裡面的資料」。

這就是封裝。

封裝的核心就是：**把欄位藏起來（private），只開放受控制的方法讓外面操作**。

這樣做有什麼好處？最大的好處是：我可以在 setter 裡加驗證邏輯。比如「存款金額不能是負的」，你在 `deposit()` 方法裡加一個 `if (amount > 0)` 判斷，以後不管誰呼叫，都不可能傳入負數存款。

另一個好處是：內部實作可以改，只要公開介面不變，外面的程式不用動一行。

---

## private 欄位 + public getter/setter

這頁程式碼就是封裝的標準長相。

`balance` 欄位宣告為 `private`——外面碰不到。

`getBalance()` 是 getter——讓外面可以「讀取」餘額，但不能直接改。

`deposit()` 是受控制的存款方法——裡面加了 `amount > 0` 的驗證，確保不會存入負數。

最後那行 `acc.balance = -999` 被標記 `❌ 編譯錯誤！`——你看，連試都試不了，編譯階段就擋掉了。這就是 `private` 的威力。

這比「希望別人不要亂改」要可靠多了，對吧？

---

## 存取修飾詞：四種層級

Java 有四種存取修飾詞，控制誰能看到什麼。

`public`：所有地方都能存取，最開放。

`protected`：同套件可以，加上不同套件的子類別也可以。

無修飾（package-private）：只有同套件內可以，外面看不到。

`private`：只有自己這個類別能用，最嚴格。

一般原則：**欄位預設選 private，方法依需求決定**。

為什麼這麼保守？因為你可以之後放寬，但你很難之後收緊——一旦你把東西設成 public，全世界都可能在用，你要改就要確認沒有人依賴它，很麻煩。

---

## 存取修飾詞比較表

這頁是比較表，直接看打勾打叉。

`public`：四格全打勾，最開放。

`protected`：前三格打勾，外部（不同套件、非子類別）打叉。

無修飾：前兩格打勾，子類別（不同套件）和外部打叉。

`private`：只有同類別打勾，其他全叉，最保守。

記憶訣：由鬆到嚴就是 `public → protected → 無修飾 → private`。從全開到全鎖。

---

## JavaBean 慣例

說到封裝，就不能不提 JavaBean。

JavaBean 不是一個語言特性，它是一個「大家說好的設計慣例」，被 Spring、Hibernate 這些主流框架廣泛採用。所以你現在學，等等學框架的時候就不會一臉茫然。

規則很簡單：

所有欄位必須是 `private`。

Getter 叫做 `getXxx()`——比如欄位叫 `name`，getter 就叫 `getName()`。

Setter 叫做 `setXxx(value)`——比如 `setName(String n)`。

布林型態的 getter 要用 `isXxx()`，不是 `getXxx()`——比如 `isActive()` 而不是 `getActive()`。這是強制規定，IDE 和框架都靠這個自動識別布林欄位。

最後，**必須有無參數建構子**，框架需要它來反射建立物件。

---

## JavaBean 慣例 — 範例

這頁程式碼是標準的 JavaBean 長相，幾乎所有你以後寫的資料類別都長這樣。

`private String name`、`private boolean active`。

然後是 `getName()`、`setName()`、`isActive()`、`setActive()`。

布林欄位的 getter 用 `isXxx()` 這件事特別容易忘，再強調一次：`isActive()` 不是 `getActive()`。

把這個範例記住，以後寫 POJO、DTO、Entity 都是這個格式。

## 類別變數 vs 實體變數

好，我問你一個問題。

公司裡每個員工有自己的辦公桌——那是「實體變數」，每個人一份，互不干擾。

但公司有一台共用印表機——那是「靜態變數」，整間公司共用一份。你用、我用，大家用的是同一台。

`static` 欄位就是那台共用印表機。它屬於**類別本身**，不屬於任何一個物件，所有物件共用同一份資料。

存取方式也不一樣：實體變數用 `obj.age`，靜態變數用 `Dog.count`——你看，是用類別名稱點，不是用物件點。這樣讀程式的人一眼就知道：喔，這是靜態的，是共用的。

---

## 類別變數 — 範例

這頁是一個計數器的例子，超常見的設計。

`Dog` 類別有一個 `static int count`，初始值是 0。

每次 `new Dog()` 的時候，建構子裡面有 `count++`，所以每建立一隻狗，計數器就加一。

最後 `Dog.count` 輸出 2——因為我們建了小黑跟小白。

這個模式在統計物件數量、產生序號、追蹤資源使用量的時候超好用。你不需要額外的管理類別，計數器就長在類別本身裡。

---

## static 方法

靜態方法就是「不需要物件就能呼叫的方法」。

你每天用的 `Math.abs()`、`Math.max()`、`Integer.parseInt()`——這些全是靜態方法。你從來沒有 `new Math()` 過，對吧？因為根本不需要。

靜態方法有一個重要限制：**不能存取實體欄位或呼叫實體方法**。

為什麼？因為靜態方法是屬於類別的，不屬於任何物件。既然沒有物件，`this.name` 指的是誰的 name？沒有答案，所以直接禁止。

靜態方法只能用：static 欄位、其他 static 方法、傳進來的參數。

---

## static 方法 — 自訂範例

這頁自己設計了一個 `MathUtils` 工具類別，裡面兩個靜態方法：加法和圓面積計算。

注意，這個類別根本不需要任何欄位——它就是一堆計算函式，沒有「狀態」可言。這種情況最適合設計為靜態方法。

呼叫方式是 `MathUtils.add(3, 4)`——直接類別名稱點，不需要 `new MathUtils()`。

這種工具類別（Utility Class）的設計方式在實際專案裡超常見，日期工具、字串工具、數學工具，通常都長這樣。

---

## static 初始化區塊

`static { }` 這個語法很多人沒看過，但其實很簡單：它在**類別第一次被 JVM 載入的時候執行，而且只執行一次**。

什麼時候需要它？

假設你的靜態變數初始化很複雜——不是簡單的 `= 100`，而是要讀取設定檔、做一堆計算——你沒辦法一行搞定，這時候就把邏輯放進 `static { }` 區塊裡。

時機上，static 初始化區塊比建構子更早執行。類別載入 → static 區塊執行 → 之後才是 `new` 和建構子。

一個類別可以有多個 static 區塊，按照出現順序執行。

---

## Singleton 設計模式簡介

最後壓軸——Singleton，設計模式裡最常被問到的一個。

Singleton 解決的問題是：**有些東西，全程式只能有一份**。比如資料庫連線池、全域設定管理器、日誌系統——你不會希望有兩個設定管理器同時存在，那會打架。

怎麼做到「只有一個物件」？三個元件：

第一，把建構子設為 `private`。外面想 `new Singleton()` 的話，編譯器直接報錯，想都別想。

第二，用 `private static` 欄位存放那個唯一的實體。

第三，提供一個 `public static getInstance()` 方法作為唯一入口。外面只能透過這個方法拿到物件，拿不到就自己建一個，然後就這一個。

這三個加在一起，就鎖死了「只有一個實體」這件事。

---

## Singleton — 使用範例

使用起來超簡單：

`Singleton s1 = Singleton.getInstance()`，第一次呼叫，裡面的 `instance` 是 null，所以建立一個新物件。

`Singleton s2 = Singleton.getInstance()`，第二次呼叫，`instance` 已經不是 null，直接返回同一個物件。

最後 `s1 == s2` 輸出 `true`——他們指向記憶體裡同一個地址，是同一個東西。

現實中 Singleton 用在哪？資料庫連線池、Logger、Config 管理器——任何「全程唯一」的資源管理員都適合這個模式。

## 練習一：設計 Student 類別

好，來到練習環節了，第一題。

你要設計一個 `Student` 類別，需求如下——

欄位：姓名和成績（0 到 100）。

兩個建構子：一個無參數版本，一個接受姓名和成績的版本。無參數的那個用 `this()` 委託給有參數的，傳入預設值 `"未知"` 和 `0`。

`setScore()` 要加驗證，拒絕 0 以下或 100 以上的值。

最後提供一個 `static isPass(int score)` 判斷是否及格，門檻是 60 分。

這道題把今天三個主題全串起來了：建構子多載、`this()` 鏈式呼叫、封裝加驗證、靜態方法。一道題抵三道。

---

## 練習一：解題提示

幾個關鍵點提示你：

`this("未知", 0)` 要寫在無參數建構子的**第一行**，不然編譯錯誤。

setter 的驗證邏輯：`if (score >= 0 && score <= 100) this.score = score`——注意是「合法才存，不合法就忽略」，不是丟例外（先這樣設計就好）。

`isPass()` 前面加 `static`，外面用 `Student.isPass(75)` 呼叫，不需要物件。

getter 和 setter 的命名要符合 JavaBean 慣例：`getName()`、`setName()`、`getScore()`、`setScore()`。

---

## 練習二：計數器與 Singleton

第二題進階一點，要你整合兩個概念。

第一個任務：在 `Student` 類別加一個 `static int totalCount`，每次 `new Student()` 的時候自動累加，最後用 `Student.totalCount` 驗證數字對不對。

第二個任務：設計一個 `SchoolConfig` 類別，用 Singleton 模式儲存學校名稱。要驗證兩次 `getInstance()` 拿到的是同一個物件。

兩個任務都不難，但很適合練手感。第一個練的是 static 欄位的生命週期，第二個練的是 Singleton 的三要素。

做完這兩題，今天教的東西你就真的消化了。

---

## 練習二：解題提示

計數器的寫法：`totalCount++` 放在**有參數建構子**裡。然後用 `this()` 委託的無參數建構子，因為最終還是會跑到有參數建構子，所以不會重複計數。

Singleton 三要素再念一次：`private` 建構子、`private static instance` 欄位、`public static getInstance()` 方法。缺一個都不叫 Singleton。

驗證方式：`c1 == c2` 比較的是記憶體位址，如果是同一個物件，一定是 `true`。如果是 `false`，代表你的 Singleton 沒寫對。
