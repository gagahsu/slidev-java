## 1-1 認識 Java（章節頁）

好，第一節：認識 Java。

你有沒有聽過這樣一種說法：「學程式語言，先選一個，學好了其他的都會了。」這句話對也不對，但有一點是真的——Java 是一個非常好的起點。

為什麼？因為它夠嚴格、夠囉唆，所以你學到的好習慣，帶到任何語言都用得上。就像練書法，你一開始被老師盯著筆順寫，很煩沒錯，但寫好了之後，你拿毛筆、鋼筆、原子筆都比別人漂亮。

Java 就是那個「讓你養成好習慣」的語言。

---

## 什麼是 Java？

那 Java 到底是什麼？

一句話說完：Java 是一個**高階、物件導向**的程式語言，1995 年由 Sun Microsystems 推出，現在由 Oracle 負責維護。

「高階」的意思是，你不需要去管 CPU 怎麼運算、記憶體在哪個位置，你只要專注在「解決問題」就好，細節讓 Java 幫你處理。

「物件導向」這個詞現在聽起來可能很抽象，但後面的課程會一直深入，你會越來越有感覺。

然後最重要的那句口號：**Write Once, Run Anywhere**——一次撰寫，到處執行。

這是 Java 最引以為傲的設計理念，意思是你在 Windows 上寫的程式，放到 Mac、放到 Linux，一樣可以跑，完全不用改。聽起來很厲害對吧？它是怎麼辦到的，我們等等 1-7 的時候會詳細說明。

現在你只需要知道一件事：**Java 無所不在。** 你用的 Google 服務、Amazon 後台、你手機的 Android App，這些背後幾乎都有 Java 的影子。全球超過一千萬名開發者在用它，這個數字不是在吹牛。

## 1-2 Java 的起源（章節頁）

好，我們往回追一下 Java 是怎麼誕生的。這段歷史其實挺有意思的，而且有一個你意想不到的故事轉折。

---

## Green Project（1991）

時間回到 1991 年。那個年代，手機還是磚頭、網路根本還沒普及，但 Sun Microsystems 的工程師已經在想一個很前衛的問題：

「如果家裡的電視、洗衣機、冰箱都能透過軟體來控制，要怎麼做？」

他們成立了一個叫做 **Green Project** 的秘密計畫，想幫各種家電設備開發控制軟體。問題是，那個年代的程式語言——像 C++——對小型裝置來說太笨重了，記憶體用一大堆，設備根本跑不起來。

所以他們決定自己打造一個全新的語言，這個語言最初叫做 **Oak**，「橡樹」的意思，據說是因為設計師辦公室外面有一棵橡樹。這名字還挺文青的。

後來 1993 年，World Wide Web 突然爆炸性成長，大家都在瘋網路，Green Project 的方向就順勢轉向了網際網路應用。

然後到了 1995 年，Oak 準備正式發表，一查才發現：這個名字已經被別人註冊商標了！

怎麼辦？只好重新想名字。傳說是開發團隊在咖啡廳討論，喝著爪哇島（Java）咖啡，靈感就來了——**Java！**

所以說，Java 這個名字其實是靠咖啡救出來的。下次你在咖啡廳寫 Java，可以告訴自己這是在致敬歷史。

## 1-3 Java 之父（章節頁）

說完了 Java 的誕生，來認識一下這個語言的靈魂人物。

---

## James Gosling — Java 之父

**James Gosling**，加拿大人，卡內基梅隆大學的電腦科學博士。他在 Sun Microsystems 擔任首席工程師，設計了 Java 語言的規格，也親手寫出了第一版的編譯器和 JVM 原型。

你想想看，這是什麼概念？他不只是「想出」一個語言，他還自己把工具鏈全部刻出來。這就好比你不只設計了一款遊戲，你還順手把遊戲引擎也寫了。

所以他被尊稱為「Java 之父」，這個稱號完全是實至名歸。

後來 Oracle 收購 Sun 之後，Gosling 在 Oracle 待了一段時間，之後輾轉去了幾家公司。雖然 Java 的維護現在是 Oracle 的事，但 Gosling 的設計哲學至今還深深影響著整個 Java 生態系。

他就是那種等級的人物。

## 1-4 Java 發展史（章節頁）

好，我們來快速看一下 Java 這三十年的成長史。你不用把每個版本都背起來，但幾個關鍵版本要有印象。

---

## Java 版本里程碑（一）

1995 年，Java 1.0 正式公開發表，Sun 大張旗鼓地宣傳 Write Once, Run Anywhere，業界一片震驚。

1998 年，Java 1.2 出來，帶了 Collections 框架，就是我們後來用的 `ArrayList`、`HashMap` 那些東西的前身。還加了 Swing，讓你可以用 Java 寫桌面視窗程式，雖然……說真的，那個 UI 設計得有點歷史感就是了。

然後是 **2004 年，Java 5**，這個版本很重要！它引入了**泛型（Generics）**。

在 Java 5 之前，你把東西放進 `List`，取出來要手動轉型。比如說放了一個 `String` 進去，取出來的是 `Object`，你要自己寫 `(String) list.get(0)` 才能用。轉錯了？程式直接在執行時爆炸。

Java 5 之後，你可以寫 `List<String>`，編譯器幫你把關，型別錯誤在寫程式的時候就被抓出來，不用等到上線才爆炸。這個改變大幅降低了 Bug 的數量。

然後 2009 年，Oracle 收購了 Sun Microsystems。這件事在 Java 社群裡引起了不少討論，有人擔心商業公司掌控了這個語言，有人則是持觀望態度。我們繼續看後來發生了什麼。

---

## Java 版本里程碑（二）

接下來幾個版本你一定要記住，特別是帶星號的 LTS 版本。

**2014 年，Java 8**，這是革命性的一個版本。它引入了 **Lambda 表達式**和 **Stream API**，讓 Java 也可以用一種更現代、更簡潔的風格寫程式。很多公司到今天還在用 Java 8，可見它有多穩定、多受歡迎。我們課程後面也會學到 Lambda 和 Stream。

**2017 年，Java 9** 帶來了模組系統，而且 Oracle 宣布從此改成**每六個月發一個新版本**。聽起來很積極，但問題是版本更新太快，企業根本跟不上，所以 Oracle 同時推出了 LTS（Long-Term Support）策略，只有 LTS 版本才提供長達八年的安全更新。

LTS 版本包括：Java 8、11、17、21。企業選工具，基本上都選這些。

我們課程用的是 **Java 17**，目前企業採用最廣泛的 LTS 版本，新特性夠多、社群夠穩定，是學習 Java 的黃金選擇。

## 1-5 Java 的三大平台（章節頁）

好，現在來看 Java 的生態系是怎麼組織的。Java 根據用途，被分成三個主要平台。

---

## Java 三大平台

第一個是 **Java SE（Standard Edition）**，標準版。這是基礎，所有東西都建在它上面。日常應用程式、學習用，都是 SE。我們課程學的就是 Java SE。

第二個是 **Java EE / Jakarta EE（Enterprise Edition）**，企業版。這是給大公司、複雜系統用的。Servlet、Spring 框架都屬於這個生態系。2019 年 Oracle 把 Java EE 移交給 Eclipse 基金會，改名叫 Jakarta EE，但概念是一樣的。

第三個是 **Java ME（Micro Edition）**，微型版。這是為資源極度受限的裝置設計的，像早期的功能型手機、嵌入式系統。不過因為 Android 的崛起，現在 Java ME 已經幾乎沒什麼存在感了。

用一個比喻來說：Java SE 是一台普通家用車，日常代步完全夠用。Java EE 是商用大貨車，要運貨、跑長途，幫企業做大事。Java ME 是那種超小的電動代步車，省電省資源，適合很窄小的地方。

打好 Java SE 的基礎，以後要往 Jakarta EE 發展，是非常自然的延伸。

---

## 1-6 JDK / JRE / JVM（章節頁）

好，我們來到今天可能最多人搞混的一個部分：JDK、JRE、JVM。

很多新手剛開始安裝 Java 環境，看到這三個縮寫就開始頭痛。今天我們把它徹底搞懂，一勞永逸。

---

## JVM / JRE / JDK 定義

先一個一個看定義，然後我再給你一個比喻：

**JVM，Java Virtual Machine，Java 虛擬機器**。它負責執行 Bytecode，也就是把「機器看得懂的中間語言」翻譯成真正的電腦指令，然後跑起來。

**JRE，Java Runtime Environment，Java 執行環境**。它等於 JVM 加上標準類別庫。你要「執行」一個 Java 程式，安裝 JRE 就夠了。

**JDK，Java Development Kit，Java 開發工具組**。它等於 JRE 加上開發工具，像是編譯器、除錯器等等。你要「開發」Java 程式，就要裝 JDK。

包含關係很清楚：**JDK 包含 JRE，JRE 包含 JVM**。裝了 JDK，就自動有了 JRE 和 JVM。

比喻來了。JVM 就是**電影放映機**，負責把電影播出來。JRE 是**電影院**，裡面有放映機，還有座位、音響、爆米花（類別庫）。JDK 是整個**電影製作公司**，除了電影院，還有攝影棚、剪接室、導演、燈光師——一切你拍電影需要的東西。

你只是要「看電影」，裝 JRE 就夠。你要「拍電影」，就得裝 JDK。我們是開發者，所以裝 JDK。

---

## JDK / JRE / JVM 包含關係

這張圖把三者的包含關係畫得非常清楚。

最核心的是 JVM，也就是那個「執行引擎」。圍繞它的是 JRE，裡面除了 JVM，還有標準類別庫——就是你呼叫 `System.out.println()` 的時候，那些方法是從哪來的？就是標準類別庫提供的，它已經幫你把常用的功能都寫好了。

最外層是 JDK，在 JRE 外面再加上開發工具，讓你可以寫程式、編譯、除錯。

記住這個包含關係，以後看到相關問題，腦袋裡要能馬上浮現這張圖。

---

## JDK 主要工具

JDK 裡面有幾個重要的工具，我帶你快速過一遍。

**javac**：編譯器。你寫的 `.java` 原始碼，用 `javac` 把它編譯成 `.class` 檔（也就是 Bytecode）。

**java**：執行工具。啟動 JVM，然後執行那個 `.class` 檔。

**jdb**：除錯工具。程式跑起來怪怪的？用 jdb 一行一行追。

**jar**：封裝工具。把一堆 `.class` 檔打包成一個 `.jar` 檔，方便發布。

**javadoc**：文件工具。你在程式裡寫的特殊格式的註解，javadoc 可以自動把它轉成 HTML 格式的 API 文件。非常方便。

說實話，現在大家都用 IDE，像 IntelliJ IDEA，這些工具都幫你包好了，你按一個按鈕，背後就幫你跑完整個流程。但了解原理，當你看到奇怪的錯誤訊息時，你才知道是哪個環節出了問題。

## 1-7 Java 跨平台原理（章節頁）

好，到了今天的重頭戲之一：Java 是怎麼做到「Write Once, Run Anywhere」的？

這個問題的答案，是 Java 設計上最精妙的地方。

---

## WORA — 一次撰寫，到處執行

關鍵就是兩個東西：**Bytecode** 和 **JVM**。

你寫了一個 `.java` 檔，用 `javac` 編譯之後，產生的不是 Windows 看得懂的機器碼，也不是 Mac 看得懂的機器碼——而是一種**平台中立**的中間語言，叫做 **Bytecode**，存在 `.class` 檔裡。

這個 Bytecode 沒有任何作業系統天生就看得懂。但每個作業系統都有自己版本的 JVM，Windows 有 Windows JVM，Mac 有 Mac JVM，Linux 有 Linux JVM。各自的 JVM 會把 Bytecode 翻譯成自己平台能執行的機器碼。

所以流程是：你的原始碼 → 一份 Bytecode → 各平台的 JVM 各自翻譯 → 在各平台跑起來。

用一個生活化的比喻：想像你用中文寫了一本食譜。你把它翻譯成一種「世界語」——沒有任何一個國家的人天生就懂，但日本有日文翻譯機，美國有英文翻譯機，法國有法文翻譯機。只要有翻譯機，每個人都能看著那本食譜，煮出一樣的料理。

Bytecode 就是那個世界語，JVM 就是各地的翻譯機。

核心概念記好：**Bytecode 是平台無關的，JVM 是平台相依的。**

---

## 編譯與執行的完整流程

來看一個具體的例子。

這是最經典的 Java 入門程式，`Hello.java`，就是印出「Hello, Java!」那幾個字。

執行步驟分兩個：

第一步，**編譯**：在命令列輸入 `javac Hello.java`，編譯器就幫你產生一個 `Hello.class` 檔，裡面裝的就是 Bytecode。

第二步，**執行**：輸入 `java Hello`，JVM 把 `Hello.class` 載入，翻譯執行，然後你就看到「Hello, Java!」出現在畫面上了。

就這樣，兩個指令。

這個流程是 Java 開發最基本的循環，不管你以後用什麼 IDE，底層都是這樣運作的。IDE 只是幫你把這些步驟包裝成一個按鈕，省了你打字的時間而已。

## 1-8 Java 語言的特色（章節頁）

最後一個大章節，我們來看 Java 有哪些語言特色，讓它能夠在三十年後還是全球最熱門的語言之一。

---

## Java 核心特色（一）

第一個是**簡單（Simple）**。這裡的「簡單」不是說 Java 很容易學，而是相對於 C++，Java 把很多複雜的機制去掉了。

最典型的是指標（Pointer）。學過 C 語言的人，應該都有被指標搞到崩潰的經驗。Java 把指標藏起來，讓你不用直接操作記憶體位址，大幅降低了一大類的 Bug。

還有多重繼承，這個概念在 C++ 裡可以造成很多混亂，Java 直接不讓你做，改用介面（Interface）來達到類似效果，更清楚、更安全。

第二個是**物件導向（Object-Oriented）**。這是 Java 的核心精神。封裝、繼承、多型，這三個概念你在後面的章節會一直碰到，一直用，一直加深理解。

第三個就是我們剛才說的**跨平台（Platform Independent）**，Write Once, Run Anywhere，不再重複了。

第四個是**安全（Secure）**。JVM 就像一個沙盒，程式在裡面跑，沒辦法直接去亂動系統記憶體，也沒辦法去讀不該讀的東西。這讓 Java 程式天生就比較安全，比較難被惡意程式利用。

---

## Java 核心特色（二）

第五個是**強健（Robust）**。Java 非常嚴格，型別不對就不讓你過。這讓很多 Bug 在寫程式階段就被抓出來，而不是等到程式上線、使用者在用的時候才爆炸。

還有一個很重要的設計：**垃圾回收（Garbage Collection，GC）**。在 C/C++ 裡，你自己申請的記憶體，要自己記得釋放，忘了就記憶體洩漏，程式跑久了越來越慢甚至崩潰。Java 的 JVM 會自動幫你回收不再使用的物件，你不用手動去 `free()`，大幅減少這類問題。

第六個是**多執行緒（Multithreaded）**。現代電腦都是多核心，Java 從一開始就內建支援多執行緒，讓你可以同時做很多事，充分利用硬體效能。

第七個是**高效能（High Performance）**。Java 早期被批評比 C++ 慢，因為它要先翻譯 Bytecode 才能執行。但後來有了 **JIT（Just-In-Time）編譯器**，它會在程式執行過程中，把常被呼叫的「熱點程式碼」直接編譯成機器碼，大幅提升執行速度。現在的 Java 在很多場景下速度已經非常接近 C++ 了。

第八個是**分散式（Distributed）**。Java 內建了網路支援的工具，非常適合開發需要多台電腦協作的系統。後來的 Spring、Netty 這些火紅的框架都建立在這個特色上。

這八個特色加在一起，就是為什麼 Java 能夠三十年屹立不搖的原因。
