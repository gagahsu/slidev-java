## 開發環境準備

在開始之前，你的電腦要先裝好「工具」，否則寫再好的程式也是白費。

Java 的開發工具叫做 **JDK**，全名是 Java Development Kit，直接翻就是「Java 開發套件」。去 jdk.java.net 下載 JDK 17，這是目前的 LTS 版本，LTS 就是「長期支援版」，意思是比較穩，不會動不動就換 API 讓你哭。

裝好之後，有兩個環境變數超重要：**JAVA_HOME** 和 **PATH**。

JAVA_HOME 是告訴電腦「我的 JDK 裝在哪裡」，PATH 是讓你在任意位置的命令列都能直接打 `javac` 和 `java`，而不是每次都要打一長串路徑。少設定其中一個，你就會看到那個讓初學者崩潰的錯誤訊息：`'javac' 不是內部或外部命令`——相信我，你不想看到它。

設定完之後，開終端機，打 `java -version`。如果看到版本號，恭喜你，環境好了！如果看到錯誤，先深呼吸，然後回去確認 PATH 有沒有設對。

---

## 我的第一個 Java 程式

好，環境搞定了，來看這段傳說中的程式碼：

```
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

五行。就這樣。

有些人第一次看到這個會覺得：「咦，感覺還好嘛。」但也有人看到 `public static void` 就腦袋開始打結。先不管它，我們等一下再逐字拆解，現在先記一件最重要的事：

**檔名必須跟 class 名稱完全一樣，包含大小寫。**

這個程式的 class 叫 `HelloWorld`，所以你的檔案名稱就要叫 `HelloWorld.java`。不能叫 `helloworld.java`，不能叫 `hello_world.java`，連一個字母差了都不行。這是 Java 的規定，不是建議，是強制的。

把它想成身分證和本人一定要一模一樣——你不可能說「名字差了一個字，但那個人是我啦」，不行的。

---

## 編譯與執行

有了 `HelloWorld.java` 之後，要怎麼讓它跑起來呢？分兩步：

**第一步，編譯。** 在終端機輸入 `javac HelloWorld.java`，按下 Enter。如果沒有錯誤訊息，你的目錄裡會多出一個 `HelloWorld.class` 的檔案。這個 `.class` 就是「Bytecode」，是給 JVM（Java 虛擬機）看的格式，人類不用讀懂它。

**第二步，執行。** 輸入 `java HelloWorld`，然後你就會看到：

```
Hello, World!
```

恭喜你，你寫出了人生第一個 Java 程式！

我現在要講一個初學者最常中的陷阱，記好了：執行的時候是 `java HelloWorld`，**不加 `.class`**。很多人會本能地打 `java HelloWorld.class`，然後看到一串錯誤，然後開始懷疑人生。其實只是多了 `.class` 三個字。這個錯誤我可以肯定全班會有人中——只要不是你就好了。

## 解析 Java 的程式結構｜章節頁

好，Hello World 跑起來了，但——你真的看懂那五行在做什麼嗎？

「public class」是什麼？「static void」又是誰？「String[] args」是火星文嗎？

別怕，我們現在就把這段程式碼「解剖」開來，每個關鍵字都要搞清楚它的任務。這就是本小節的重點：理解，不只是執行。

---

## Java 程式完整結構

先看完整的 Java 原始碼架構，從上到下分四個區塊。

**第一個**是套件宣告，`package com.example`。這是用來組織程式碼用的，就像資料夾幫你分類檔案一樣。初學階段可以先不寫，等程式比較大了再來學怎麼用。

**第二個**是 import，匯入外部類別。如果你要用 JDK 提供的工具——比如讓使用者輸入資料的 Scanner——就要在這裡宣告「我要用這個」，就像借書要先登記一樣。

**第三個**是 class 宣告，這是整個程式的「外殼」，所有的方法和資料都要包在裡面。

**第四個**是 main 方法，這是程式正式開始執行的地方。把整個 Java 程式想成一本書，main 就是第一頁，JVM 翻開書就從這裡開始讀。

---

## class 宣告解析

我們拉近來看 `public class HelloWorld { }` 這行，一個字一個字解釋：

**`public`** 是存取修飾詞，代表這個類別對所有人公開。先記住：public 就是「公開的」。

**`class`** 是 Java 的關鍵字，表示你正在定義一個「類別」。類別是 Java 最基本的組成單位，像是一個容器，把相關的方法和資料打包在一起。

**`HelloWorld`** 是類別名稱，你來取的。Java 的命名慣例是 Pascal Case——每個單字的第一個字母都大寫。像 `HelloWorld`、`BankAccount`、`StudentManager`，看到大寫開頭你就知道這是個類別。

**`{ }`** 大括號就是類別的本體，所有的方法都要寫在這對括號裡面。

還有一個重點：一個 `.java` 檔案裡只能有一個 `public class`，而且這個 class 的名稱必須跟檔名完全一致。這規則很死板，但就是這樣。

---

## main 方法完整解析

接下來是 Java 世界裡最重要的一行：

```
public static void main(String[] args)
```

這行有五個關鍵字，缺一不可。我們逐一講：

**`public`**：JVM 從外部呼叫這個方法，所以要設成公開。

**`static`**：不需要建立物件就能呼叫。JVM 啟動的時候沒有物件，但它需要找到 main，所以 main 必須是 static 的。這個概念之後學到物件導向你會更懂，現在先記著就好。

**`void`**：這個方法不回傳任何值。執行完就結束了，沒有回應。

**`main`**：這是固定名稱，JVM 啟動時會專門找這個名字。不能叫 Main、不能叫 MAIN，就是全小寫的 main。

**`String[] args`**：這是命令列引數，讓你在執行程式時從外部傳資料進去。初學階段先把它當成「一定要寫但暫時不管它的東西」就好，就像租車合約裡那些小字——你知道它在那裡，但先不管。

這整行你最好背起來，因為每個可執行的 Java 程式都有它。

---

## 控制台輸出方法

程式要跟你說話，就靠輸出。Java 有三種輸出方法：

**`System.out.println(x)`**：印出 x 之後換行。這是你最常用的，幾乎每個範例都會看到。

**`System.out.print(x)`**：印出 x，但不換行。如果你想要同一行連續輸出兩個東西，就用這個。

**`System.out.printf(fmt, ...)`**：格式化輸出。這個比較進階，讓你精確控制輸出格式，像是小數只顯示兩位、數字靠右對齊之類的。注意 `%n` 是跨平台的換行符號，比直接寫 `\n` 更建議使用。

說真的，你現在最需要的就是 `println`，另外兩個有用到再回來查。先把最常用的搞熟，其他的自然水到渠成。

---

## 命名慣例總整理

Java 有一套大家默默遵守的命名慣例，不遵守程式照樣跑，但你的同事會在心裡默默翻白眼。

**類別**用 Pascal Case，每個單字首字母大寫：`HelloWorld`、`BankAccount`。

**方法和變數**用 camelCase，第一個字小寫、後面每個單字首字母大寫：`printMessage`、`userName`。

**常數**全大寫，單字用底線分開：`MAX_SIZE`、`PI`。

**套件名稱**全小寫，用點分隔：`com.example.app`。

這些規則的意義在於「讀程式碼的速度」。當你看到一個大寫開頭的東西，你的大腦馬上知道這是類別。看到全大寫，你知道這是常數。這種隱含的資訊讓你讀別人的程式碼時快很多，也讓別人讀你的程式碼時不用多費腦力。

這是你對團隊的尊重，也是專業素養的一部分。

## 程式註解｜章節頁

OK，最後一個章節：程式註解。

你有沒有過這種經驗——打開上個月自己寫的程式，然後看著螢幕問：「這是我寫的？這在幹嘛？」

這就是「沒有寫好註解」的下場。而且這不只發生在別人身上，會發生在每個人身上，包括你。

好的程式碼除了能跑，還要讓三個月後的自己，甚至是你的同事，看得懂在做什麼。這就是「註解」存在的意義——它是給人看的，不是給電腦看的。

---

## 三種註解類型

Java 有三種註解類型，你要根據場合選對工具：

**單行註解** `//`：最簡單，兩條斜線後面跟說明文字。適合對單行程式碼做快速說明。

**多行註解** `/* */`：從 `/*` 到 `*/`，中間可以跨很多行。適合解釋比較複雜的邏輯，或是暫時把一大段程式碼「關掉」。

**文件註解** `/** */`：以兩個星號開頭，這是最正式的一種，專門用來產生 Javadoc API 文件。

有一件事要特別說：這三種註解，javac 在編譯時全部都會無視掉，完全不影響執行結果。所以你可以放心寫，不用擔心「加了註解程式會跑慢」——不會的，放一百個也沒差。

---

## 單行註解（//）

單行註解最直觀，`//` 之後到行尾的所有文字都是註解，編譯器完全忽略。

可以獨佔一整行，寫在程式碼上方，說明接下來那段在做什麼：

```java
// 印出歡迎訊息到控制台
System.out.println("Hello, World!");
```

也可以直接跟在程式碼後面，做行尾備註：

```java
int count = 0; // 計數器，初始值為 0
```

還有一個超好用的場景：Debug 的時候，想暫時把某行程式碼「停用」，不用刪掉它，只要在前面加 `//` 就好，測完再拿掉。這招你一定會常常用到。

---

## 多行註解（/* */）

多行註解從 `/*` 開始，到 `*/` 結束，中間可以跨任意多行。

最常見的使用場景是，在一個比較複雜的方法上方，說明它的邏輯、用了什麼演算法、或是時間複雜度。像這樣：

```java
/*
 * 計算兩個整數的最大公因數
 * 使用輾轉相除法（歐幾里得演算法）
 */
```

看到這段，你馬上知道這個方法在幹嘛，不需要一行一行讀程式碼去猜。

另一個常用場景：Debug 時想要暫時停用一大段程式碼，用 `/* */` 把它包起來比一行一行加 `//` 快多了。這叫「comment out」，工程師的日常。

---

## 文件註解（Javadoc）

文件註解是三種裡最「有架子」的一種，以 `/**` 開頭，用在類別或方法的正上方。

它的特別之處在於：執行 `javadoc` 工具之後，這些註解可以自動產生 HTML 格式的 API 文件，就像你在 Oracle 官網看到的那種——方法名稱、參數說明、回傳值，整整齊齊排好。

範例長這樣：

```java
/**
 * 計算兩數之和並回傳結果。
 *
 * @param a 第一個整數
 * @param b 第二個整數
 * @return 兩數相加的結果
 */
public int add(int a, int b) {
    return a + b;
}
```

在公司開發時，這是標準的文件化方式。你讓其他工程師不需要看你的程式碼，就能知道這個方法怎麼用、傳什麼、回傳什麼。這就是尊重別人的時間，也是讓自己顯得專業的方式。

---

## 常用 Javadoc 標籤

Javadoc 有幾個常用標籤，先記最重要的幾個：

**`@param 名稱 說明`**：描述這個方法需要什麼輸入，每個參數各寫一行。

**`@return 說明`**：描述這個方法會回傳什麼。

**`@throws 例外 說明`**：如果這個方法可能拋出例外，要在這裡說明。

**`@author`、`@version`、`@since`** 這三個是放在類別層級的，說明作者、版本號、從哪個版本開始有這個功能。

在業界，至少要在所有 `public` 方法上補好 `@param` 和 `@return`。至於寫得多詳細，看公司的規範。但有寫跟沒寫，給人的印象差很多。

建議你去讀讀 Spring Framework 的 Javadoc，他們寫得非常完整，是很好的學習範本。

## 練習一｜從零跑出第一個程式

好，理論說夠了，來真的！

第一個練習很單純：建立一個類別叫 `MyProfile`，在 main 方法裡用 `System.out.println()` 分三行印出你的姓名、你正在學習 Java、以及今天的日期。

聽起來很簡單，對吧？但這個練習的用意是讓你走過「建立檔案 → 編譯 → 執行」的完整流程。不是貼程式碼，是你自己從一個空資料夾開始，親手打出來、親手編譯、親手執行。

這個循環——寫程式、編譯、看結果、修改、再跑——就是你未來每天要做的事。現在就讓它成為你的肌肉記憶。

---

## 練習一｜解題提示

有幾個提示幫你避開地雷：

第一：建立 `MyProfile.java`，記住檔名和 class 名稱要完全一致，大小寫也算。

第二：在 main 裡面用三個獨立的 `System.out.println()` 印出三行，不要塞在同一行裡。

第三：編譯用 `javac MyProfile.java`，執行用 `java MyProfile`，不加 `.class`。

如果你看到「找不到或無法載入主要類別」，通常是類別名稱或執行指令有拼錯。如果看到「無法找到符號 System」，去確認大括號有沒有配對好。

成功跑出三行之後，試著改改文字再跑一次。感受那個「改了就能馬上看到結果」的快感——這就是寫程式最爽的地方之一。

---

## 練習二｜寫一段有完整註解的程式

第二個練習稍微進階：我們給你一段 Calculator 的程式碼，裡面有個 `add` 方法和 main 方法。

你的任務是：幫 `add` 方法加上完整的 Javadoc 文件註解，包含 `@param` 和 `@return`；然後在 main 方法裡面加上至少兩個單行註解。

這個練習不是要你把每行都加上註解——那叫做「過度註解」，反而會讓程式碼更難讀。重點是在「需要說明」的地方，寫上「有意義的說明」。

好的註解是解釋「為什麼這樣做」，而不只是「做了什麼」。「`a = a + 1`，把 a 加一」——這種廢話不用寫，程式碼本身就說清楚了。

---

## 練習二｜解題提示

提示：Javadoc 文件註解要放在 `add` 方法定義的**正上方**，不是裡面，不是下面，是正上方。

格式是：

```java
/**
 * @param a ...
 * @param b ...
 * @return ...
 */
```

裡面那些星號 `*` 不是強制的，但這是業界標準，寫出來更好看也更專業。

完成之後，可以試著執行 `javadoc Calculator.java`，它會在你的目錄裡產生一堆 HTML 檔。用瀏覽器打開 `index.html`，你會看到一份正式的 API 文件——就跟官方文件長得一模一樣。那個成就感，絕對值得你試試看。
