# Slide Upgrade

讀取現有 Slidev 投影片，對照目標 JDK 版本的完整 API，找出缺漏的知識點，並補充新投影片到現有檔案中。

## 觸發時機

- 「檢查 @ch12-char-string.md 有沒有遺漏 JDK 17 的內容」
- 「幫我補充 @ch13-regex.md 缺少的部分」
- 「升級 @xxx.md 到 JDK 17」
- 「@ch12-char-string.md 有哪些 JDK 11/17 新特性沒講到？」

## 執行流程

### Step 1：讀取現有投影片

讀取使用者指定的 `.md` 投影片檔案，整理出：
1. **主題名稱**（例如：String 類別、Collection Framework）
2. **已涵蓋的知識點清單**：每個頁面標題 + 涵蓋的方法/概念
3. **目標 JDK 版本**：從使用者指定中取得，未指定時預設為 **JDK 17**

### Step 2：搜尋目標 JDK 的完整 API 覆蓋範圍

使用偏好來源清單搜尋，找出目標 JDK 版本對此主題的所有支援內容：

#### 偏好來源清單（依優先順序）

| 優先級 | 網站 | 特性 |
| --- | --- | --- |
| ★★★ | `dev.java` | Oracle 官方，Java 8–17 特性最權威 |
| ★★★ | `baeldung.com` | 深度詳盡，通常會標注「Java X 新增」|
| ★★★ | `digitalocean.com/community/tutorials` | 結構清晰 |
| ★★★ | `geeksforgeeks.org` | 涵蓋廣，格式一致 |
| ★★ | `docs.oracle.com` | Javadoc，確認方法簽名與版本標注 |

**搜尋策略：**

```
<主題> JDK 17 new features site:dev.java
<主題> java 11 17 new methods site:baeldung.com
<主題> complete API java 17 site:geeksforgeeks.org
```

WebFetch **至少 2 個**偏好來源，重點抓取：
- 哪些方法 / 語法是 Java 9、10、11、12、13、14、15、16、17 新增的
- 每個新增項目的語法、用途、程式碼範例

### Step 3：比對缺口，並為每個缺漏項目找出天然歸屬位置

將「搜尋到的完整清單」與「投影片已涵蓋的知識點」逐一對照，**同時為每個缺漏項目指定它應插入的現有頁面旁**：

規則：
- 與現有某張投影片概念相鄰的（例如 `strip()` 和 `trim()` 相關），插入在那張**之後**
- 與現有某個章節（Part）相關的，插入在該章節**末尾、練習題之前**
- 若真的找不到相關章節，才考慮放在所有練習題結束後、Q&A 之前

**輸出格式（給使用者確認）：**

```
比對結果：@ch12-char-string.md（目標：JDK 17）

已涵蓋（略過）
  - length()、isEmpty()、isBlank()、trim()、indexOf() ...

建議補充（共 N 項）
  1. strip() / stripLeading() / stripTrailing()
     → 插入位置：trim() 投影片之後
  2. repeat(int count)
     → 插入位置：字串的串接（concat）之後
  3. lines()
     → 插入位置：String.join() 之後（Part 3 末尾）
  4. Text Blocks """..."""
     → 插入位置：Part 2「基本字串宣告」之後
  5. startsWith() / endsWith()
     → 插入位置：contains() 那張之後

是否要補充到 @ch12-char-string.md？(全部 / 選擇編號 / 取消)
```

### Step 4：等待使用者確認

**不要直接修改檔案**，先等待使用者回應：
- 「全部」→ 補充全部缺漏項目
- 「選擇 1 3 4」→ 只補充指定的項目
- 「取消」→ 不做任何修改

### Step 5：產生並插入新投影片

針對使用者確認的項目，依照下方「排版規則」產生投影片內容，並**依 Step 3 規劃的位置逐一插入**。

#### 插入位置原則（優先順序）

1. **緊鄰相關投影片** — 與現有某張投影片概念直接相關（例如 `strip()` 接在 `trim()` 後），直接插在那張後面
2. **章節末尾** — 屬於某個 Part 的內容但沒有明確對應頁，插在該 Part 最後一張方法頁與練習題之間
3. **Q&A 之前** — 真的無法歸入任何現有章節時，才放在 Q&A 前

**禁止建立獨立的「補充」章節** — 新內容應融入現有結構，不要在最後加一個 section 標題為「補充」的區塊

## 排版規則（與 web-slides 相同）

### 頁面類型

| 類型 | 使用時機 | Frontmatter |
| --- | --- | --- |
| 內容頁 | 一般內容 | 無（預設） |
| 章節分隔 | 補充項目超過 3 個大主題時可選擇加 | `layout: section` |

### 方法說明頁

**一律用「表格 + 程式碼區塊」，禁止用條列式。不標注版本號，專注語法與範例。**

```markdown
# 方法名稱

| 方法名稱 | 說明 |
| --- | --- |
| `method(param)` | 功能說明 |

```java
// 程式碼範例
```
```

**表格列數 ≥ 5 且搭配程式碼時，強制拆成兩張頁面**

### 程式碼區塊

- 一律標註語言：` ```java `
- **行數上限**：純程式碼頁最多 **9 行**；同一頁有表格時最多 **5 行**

### 補充說明（Callout）

```html
<div class="mt-4 p-3 bg-blue-50 border-l-4 border-blue-400 text-gray-700 text-sm text-left">
💡 <b>標題：</b> 說明文字
</div>
```

## 內容產生原則

1. **只補充真正缺漏的** — 已有類似內容的方法不重複加入
2. **語法 + 範例優先** — 每個新增頁面都要有表格說明與可執行的程式碼範例，不標注版本號
3. **最簡範例開場** — 第一個程式碼範例從最簡單用法開始
4. **融入現有結構** — 新投影片插入天然歸屬位置，禁止建立獨立「補充」章節；若多個新項目都找不到歸屬，才可在 Q&A 前統一插入
5. **不修改現有投影片內容** — 只插入新頁，不改動原有頁面文字
6. **不碰 index.md** — 此 skill 完全不修改 index.md

## 完成後輸出

告知使用者：
1. 在哪個檔案（`@xxx.md`）補充了幾張投影片
2. 補充的項目清單（方法名 + Java 版本）
3. 插入的位置（Q&A 前 / 哪個章節後）
4. 執行 `pnpm dev` 即可預覽新內容
